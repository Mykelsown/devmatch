## 4. CRITICAL RESEARCH — do NOT redo this (30+ min saved)

### R1. Browser Lace wallet (dapp-connector-api v4.0.1)

- Lace injects `InitialAPI` at `window.midnight.mnLace`.
- `InitialAPI.connect(networkId: string): Promise<ConnectedAPI>` — the modern API is **`connect(networkId)`**, there is NO `enable()`.
- `ConnectedAPI` (= `WalletConnectedAPI & HintUsage`) key methods:
  - `getShieldedBalances()`, `getUnshieldedBalances()`, `getDustBalance()`
  - `getShieldedAddresses()` → `{ shieldedAddress, shieldedCoinPublicKey, shieldedEncryptionPublicKey }` (bech32m strings)
  - `getUnshieldedAddress()` → `{ unshieldedAddress }`
  - `balanceUnsealedTransaction(tx: string, options?)` → `{ tx: string }` (serialized txs!)
  - `submitTransaction(tx: string): Promise<void>`
  - `getProvingProvider(keyMaterialProvider)` → in-wallet proving
  - `getConfiguration()` → `{ indexerUri, indexerWsUri, substrateNodeUri, networkId, proverServerUri? }` — use this to check network mismatch
  - `getConnectionStatus()`, `hintUsage(methodNames)`
- Types live in `@midnight-ntwrk/dapp-connector-api` (installed). `window.midnight` is `{ [key: string]: InitialAPI }` via the package's global declaration.

### R2. midnight-js provider interfaces (v4.1.1) — IMPORTANT SHAPE CHANGE

```ts
interface WalletProvider {
  balanceTx(tx: UnboundTransaction, ttl?: Date): Promise<FinalizedTransaction>;
  getCoinPublicKey(): CoinPublicKey;          // synchronous, returns key object/hex
  getEncryptionPublicKey(): EncPublicKey;     // synchronous
}
interface MidnightProvider { submitTx(tx: FinalizedTransaction): Promise<TransactionId>; }
interface MidnightProviders {
  privateStateProvider; publicDataProvider; zkConfigProvider;
  proofProvider; walletProvider; midnightProvider; loggerProvider?;
}
```

Note: **submitTx is on `midnightProvider`, not on `walletProvider`.** A `walletProvider`
built from Lace must therefore pair with a `midnightProvider` that calls
`api.submitTransaction(...)`. See `lib/wallet-provider.ts` (already drafted — review the
serialization helpers; they are the riskiest part).

⚠️ **KNOWN BUG in the drafted `lib/wallet-provider.ts`:** it returns a **Promise** from
`getCoinPublicKey()` / `getEncryptionPublicKey()` (`api.getShieldedAddresses().then(...)`),
but the midnight-js 4.1.1 `WalletProvider` interface declares these as **synchronous**
returns. This will fail to typecheck as-is. FIX: cache the shielded keys once at connect
time (fetch `getShieldedAddresses()` when the wallet connects) and return the cached
values synchronously from `getCoinPublicKey`/`getEncryptionPublicKey`.

### R3. Connect to an existing contract in 4.1.1

- `findDeployedContract(providers, options)` is the correct function (grep of
  `midnight-js-contracts/dist/index.d.mts` confirmed; `connectContract` is NOT exported).
- Options: `{ compiledContract, contractAddress, privateStateId, initialPrivateState }`
  (the store-private-state variant). `FoundContract` exposes `deployTxData`, `callTx`, and maintenance interfaces.
- `callTx.<circuit>` returns `Promise<FinalizedCallTxData>`; `CallResult` has
  `nextContractState`, `publicTranscript`, `input`, `output`, `result`, `nextPrivateState`.
- `CircuitCallTxInterface` per circuit: `(...args) => Promise<FinalizedCallTxData>`.

### R4. Browser-compatible provider packages (all exist on npm @ 4.1.1)

- `@midnight-ntwrk/midnight-js-fetch-zk-config-provider` → `FetchZkConfigProvider(baseURL)` (fetch zkir/keys over HTTP).
- `@midnight-ntwrk/midnight-js-dapp-connector-proof-provider` → `dappConnectorProofProvider(api, zkConfigProvider, costModel)` (uses wallet `getProvingProvider`).
- `@midnight-ntwrk/midnight-js-level-private-state-provider` → browser-compatible (description says "browser localStorage or Node.js file storage"). Config keys: `midnightDbName`, `privateStateStoreName`, `signingKeyStoreName`, `accountId`, `privateStoragePasswordProvider` (password must meet `validatePassword` policy: >= 16 chars, 3 of 4 char classes).
- `@midnight-ntwrk/midnight-js-indexer-public-data-provider` → `indexerPublicDataProvider(uri, wsUri)` (isomorphic-ws, browser OK).
- `@midnight-ntwrk/midnight-js-http-client-proof-provider` → `httpClientProofProvider(url, zkConfigProvider, config?)`.
- **Proof location decision (matters for the demo video):** the challenge spec says "proof
  generated locally in the browser." `httpClientProofProvider` actually generates proofs on
  the **proof server** (the local docker container at `127.0.0.1:6300`), not in the browser
  tab. To literally satisfy "in-browser proving," use `dappConnectorProofProvider(api,
  zkConfigProvider, costModel)` from `@midnight-ntwrk/midnight-js-dapp-connector-proof-provider`,
  which delegates to the wallet's `getProvingProvider`. Decide which story the demo video
  tells before wiring proofs.
- **costModel source:** `dappConnectorProofProvider` takes a `CostModel` (from
  `@midnight-ntwrk/midnight-js-protocol/ledger`). Look for a helper that derives it from
  `LedgerParameters.initialParameters()` (used in `src/deploy.ts`) or a
  `costModelFromLedgerParams`-style util in the protocol package before wiring it.

### R5. The compiled DevMatch contract API (from `contracts/managed/dev_profile/contract/index.d.ts`)

```ts
enum Tier { Yellow = 0, Green = 1 }
enum RevealPolicy { ScoreOnly = 0, FieldsOnPolicy = 1, ApprovalRequired = 2 }
type Witnesses<PS> = { localSecretKey(context): [PS, Uint8Array] };
// registerProfile(context, commitment_0: Uint8Array, tier_0: Tier, policy_0: RevealPolicy): CircuitResults<PS, []>
// Ledger: profiles: Map<Bytes32, Bytes32>, tiers, revealPolicies
```

### R6. How the caller ID works (sybil guard)

`callerId = persistentHash([pad(32, "devmatch:caller:"), localSecretKey])` — disclosed in the
ledger as the map key. For the frontend, `localSecretKey` **must be stable per wallet**, else
every `registerProfile` call mints a new identity. Recommended: derive 32 bytes from the
wallet's unshielded address (e.g. SHA-256 of `"devmatch:secret:" + address`) so caller ID is
stable across sessions. Keep the witness private (never log it).

### R7. Deployment script uses this proven flow (mirror it for the browser)

`deploy.ts` builds providers with:
- `levelPrivateStateProvider` (store name `dev_profile-state`)
- `indexerPublicDataProvider(config.indexer, config.indexerWS)`
- `httpClientProofProvider(config.proofServer, zkConfigProvider)`
- walletProvider with `balanceTx` via `wallet.balanceUnboundTransaction` + `finalizeRecipe`
- witnesses: `localSecretKey` returning a random 32-byte `Uint8Array`

### R8. Other notes

- `@midnight-ntwrk/midnight-js` barrel = `{ contracts, networkId, types, utils }`.
- `@midnight-ntwrk/midnight-js-protocol` = `{ compactJs, compactRuntime, ledger, onchainRuntime, platform }`.
- Compact runtime exports `persistentHash`/`pad`/`Vector` are available through `compact-runtime`; the generated contract already imports it.
- `setNetworkId(networkId)` from `@midnight-ntwrk/midnight-js-network-id` must run before contract ops.
- The `level` npm package has a `browser.js` build (IndexedDB) — good for `levelPrivateStateProvider`.
- Installed ledger version: `@midnight-ntwrk/ledger-v8@8.1.0`; `CoinPublicKey = string` (hex) in ledger-v8 types.
